# 2.6 本章小结

## 开篇：这一章解决了什么问题


> **📌 学习目标**
> - 掌握 DataFrame 的懒加载与表达式优化机制
> - 能用 `window()` 创建滑动窗口进行时序分析
> - 理解 DataFrame 与数据库查询的等价性

数据分析师 80% 的时间花在「清洗、探索、切片」上——这些正是 DataFrame 的专长。学完这章，你应该能：

**拿到一个脏乱的 CSV，清理干净，转换成数值矩阵，然后喂给机器学习模型。**

这听起来是基本功，但现实中的数据：字符串列混在一起、缺失值到处是、异常值拉低模型性能、类别变量需要编码——每一步都有坑。

典型流水线：脏 CSV → 缺失值处理 → 异常值检测 → 特征工程 → `toMatrix()` → ML 模型。

## 2.6.1 知识地图

```
DataFrame（结构化表格数据）
  ├── 创建
  │   ├── DataFrame.readCsv(path, sep, hasHeader)   ← CSV 加载
  │   ├── new DataFrame(List<Column>)               ← 从列列表
  │   └── new DataFrame() → addColumn()              ← 动态构建
  │
  ├── 属性查询
  │   ├── df.shape()          → [行数, 列数]
  │   ├── df.getColumnNames() → List<String>
  │   ├── df.getColumnTypes() → List<ColumnType>
  │   ├── df.get(int/负数)    → Column（按位置）
  │   └── df.getColumnByName()→ Column（按名称）
  │
  ├── 切片
  │   ├── df.sliceColumn(start, end, step)          ← 仅列维度
  │   └── df.slice(rowExp, colExp)                  ← 行+列，NumPy 语法
  │
  ├── 转换
  │   ├── df.toMatrix()     → IMatrix（仅 Numeric 列）
  │   ├── col.toVec()       → IVector（仅 Numeric 列）
  │   ├── col.toStringList()→ List<String>（通用）
  │   └── df.toCsv(path)    → CSV 导出
  │
  └── 与其他章节衔接
      ├── → 第 1 章：toMatrix() → IMatrix → 线性代数运算
      ├── → 第 4 章：数值列 toVec() → 统计量（均值/方差/偏度/峰度）
      └── → 第 5 章：IMatrix → ML.fit() → 监督学习模型
```

## 2.6.2 核心 API 一览

| 类别 | API | 说明 |
|------|-----|------|
| **CSV I/O** | `DataFrame.readCsv(path)` | 默认逗号分隔、有表头 |
| | `DataFrame.readCsv(path, sep, hasHeader)` | 自定义分隔符 |
| | `df.toCsv(path)` | 导出 CSV（含表头）|
| **属性** | `df.shape()` | `[行数, 列数]` |
| | `df.getColumnNames()` | 所有列名 |
| | `df.getColumnTypes()` | 所有列类型 |
| **访问** | `df.get(int)` / `df.get(-k)` | 按位置（含负数）|
| | `df.getColumnByName(name)` | 按列名 |
| **切片** | `df.sliceColumn(start, end, step)` | 列切片（整数索引）|
| | `df.slice(rowExp, colExp)` | 通用切片（表达式）|
| **转换** | `df.toMatrix()` | Numeric 列 → IMatrix |
| | `col.toVec()` | Numeric 列 → IVector |
| | `col.toStringList()` | 任意列 → 字符串列表 |

## 2.6.3 常见错误与解决

| 错误 | 原因 | 解决方法 |
|------|------|----------|
| `IllegalArgumentException: 列数据长度 N 与现有行数 M 不匹配` | `addColumn` 时列长度与已有行数不一致 | 确保同一 DataFrame 所有列等长 |
| `IllegalStateException: 没有Float类型的列可以转换为矩阵` | 所有列都是 String 类型 | `toMatrix()` 前确认有 Numeric 列 |
| `IndexOutOfBoundsException: 列位置 K 超出范围` | 索引越界 | 用 `df.shape()` 先确认形状 |
| 切片后数据错位 | 误用 `sliceColumn(start, end)` 而非 `slice("start:stop", null)` | 行切片用 `slice(rowExp, null)` |

## 2.6.4 与 pandas 用法对照

| 操作 | 本库 | pandas |
|------|------|--------|
| 从 CSV 加载 | `DataFrame.readCsv("f.csv", ",", true)` | `pd.read_csv("f.csv")` |
| 形状 | `df.shape()` | `df.shape` |
| 列名 | `df.getColumnNames()` | `df.columns` |
| 按位置取列 | `df.get(0)` | `df.iloc[:, 0]` |
| 按名称取列 | `df.getColumnByName("age")` | `df["age"]` |
| 取前 N 行 | `df.slice("0:N", null)` | `df.head(N)` |
| 取特定列 | `df.slice(null, "0:2")` | `df.iloc[:, :2]` |
| 导出 CSV | `df.toCsv("out.csv")` | `df.to_csv("out.csv")` |
| 转 numpy | `df.toMatrix()` | `df.values` |
| 过滤行 | 需用 slice 配合循环 | `df[df["age"] > 30]` |

## 2.6.5 典型数据处理流水线

```
脏 CSV → DataFrame.readCsv()
    ↓
缺失值处理（均值填充 / 删除行）
    ↓
异常值检测（3σ原则 / IQR）
    ↓
特征工程（One-Hot 编码 / 对数变换 / 标准化）
    ↓
df.toMatrix() → IMatrix<Double>
    ↓
ML.logisticRegression().fit(X, y)
```

## 2.6.6 与其他章节的联系

- **第 1 章线性代数**：`toMatrix()` 之后，DataFrame 的数值列就是 `IMatrix`——矩阵分解、SVD、PCA 全部可以直接用
- **第 5 章机器学习**：机器学习模型只认数值矩阵；DataFrame 的 pipeline 终点就是 ML 模型的输入
- **第 3 章可视化**：统计摘要可以快速画成柱状图或箱线图

## 2.6.7 常见误区

1. **忘记处理缺失值就跑模型**：大多数 ML 模型不支持 `NaN`，`fillNa()` 或 `dropna()` 是必做功课
2. **把字符串列直接喂给模型**：模型只认 `double`，字符串列需要 `toVec()` 转换或 One-Hot 编码
3. **不做 train/test 分割就直接评估**：在训练集上评估模型是自我欺骗——永远留出测试集
4. **忽略数据类型不匹配**：`ColumnType` 有 `DOUBLE`、`INTEGER`、`STRING`、`BOOLEAN`——混用会导致运行时异常

## 本节小结

DataFrame 是数据分析的通用数据容器，它的优势在于：表格形式天然对应关系型数据库和电子表格；统一的 API 支持从 CSV 读取、数据切分、聚合到输出的完整流程。

**核心要点**：
- DataFrame 的核心操作：readCsv、groupBy、agg、filter、toMatrix
- 与 pandas 的主要区别：强类型系统 + Java 生态
- 数据清洗的最佳实践：先了解数据质量，再决定清洗策略
