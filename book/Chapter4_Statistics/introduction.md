# 第 4 章：统计学——你看到的数据，是真相还是噪声？

## 开场：那个让产品经理兴奋了 2% 的转化率

周一早上，数据分析师小王对上周的 AB 测试数据做了个汇报：

> 「新功能上线后，实验组转化率 8.2%，对照组 6.1%，提升了 **2.1 个百分点**！建议全量上线！」

产品经理眼睛一亮，运营总监点头，这事就这么定了。

——但如果你是决策者，你敢直接拍板吗？

这里有个细思极恐的问题：**这 2.1 个百分点的差距，是新功能真的有效，还是纯粹运气好（随机波动）？**

如果再跑一轮同样的测试，差距会不会变成 0.3%？或者变成了 -0.5%？

统计学回答的正是这个问题：**在数据噪声里，怎么判断观察到的差异是真实的，还是随机产生的？** 一旦你掌握了它，你就不再只是「报数的」，而是真正能「用数据做决策」的人。

---

## 学完这章你能做什么？

- 拿到一组销售数据，判断「增长是趋势还是昙花一现」——**假设检验**
- 问卷调查结果说「女性平均工资比男性低 15%」——但样本量只有 200 人，这结论靠谱吗——**置信区间**
- 工厂说「这批零件质量比上批好」——怎么用数据证明，而不是凭感觉——**t 检验**
- 市场部说「三种广告文案效果有显著差异」——该选哪个——**ANOVA**
- 垃圾邮件过滤器说「根据你标记的数据，先验概率更新后 P(垃圾|出现"免费")=0.93」——**贝叶斯推断**

这五条对应着统计学的五大核心技能。

## 统计学与产业决策的对应

| 产业场景 | 统计学工具 | 本章位置 |
|----------|-----------|----------|
| AB 测试判断功能是否有效 | 假设检验（t 检验） | 4.3 |
| 问卷/调研的误差范围 | 置信区间 | 4.3 |
| 多组方案比较（广告/文案/设计） | ANOVA | 4.4 |
| 质量控制（工厂零件检测） | 假设检验 + 置信区间 | 4.6 |
| 推荐系统更新后用户留存是否提升 | 配对 t 检验 | 4.6 |
| Spam 过滤、疾病诊断 | 贝叶斯推断 | 4.5 |
| 金融风险度量（VaR、波动率） | 大数定律 + 中心极限定理 | 4.1 |

## 本章知识地图

```
统计学
  ├── 抽样与极限定理（4.1）
  │     搞懂：为什么「样本够大」就能推断总体——大数定律 + 中心极限定理
  ├── 概率分布族（4.2）
  │     搞懂：正态、t、卡方、F、泊松——这些分布各自描述什么场景
  ├── 参数估计与假设检验（4.3）
  │     搞懂：点估计、区间估计、p 值、两类错误——用数据做决策的整套逻辑
  ├── ANOVA（4.4）
  │     搞懂：三组以上怎么比较，而不是两两 t 检验（后者会导致多重比较错误）
  ├── 贝叶斯推断（4.5）
  │     搞懂：把「先验知识」和「数据证据」结合——比频率学派更直观的推断方式
  └── 工业案例（4.6）
        质量控制、药物试验、用户留存——三个真实决策场景
```

## 统计学在 YiShape-Math 中的位置

```java
Stats.norm(mean, std)        // 正态分布
Stats.t(degreesOfFreedom)    // t 分布
Stats.chi2(df)               // 卡方分布
Stats.f(df1, df2)            // F 分布
Stats.beta(a, b)             // Beta 分布（贝叶斯共轭先验）
Stats.poisson(lambda)        // 泊松分布
```

假设检验和参数估计也通过 `Stats.tester` 和 `Stats.estimator` 门面提供。

> **风格约定**：统计量（均值、方差）从向量上直接调用；分布对象由 `Stats` 工厂创建；检验结果用 `TestingResult`（字段 `p`、`ci`、`statistic`）——见各节 API 表。
